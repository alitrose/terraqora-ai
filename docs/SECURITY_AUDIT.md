## 1. Executive Summary

A comprehensive application security audit of TerraQora AI was performed across the backend architecture, frontend client layer, ML pipeline loading routines, file upload handlers, database query constructions, and full Git commit history.

The audit verified that the application implements defense-in-depth:
- Zero raw SQL query string interpolation (100% parametrized via SQLAlchemy 2.0 ORM and Core).
- Cryptographic password hashing using PBKDF2-HMAC-SHA256 with 600,000 iterations and per-user salt.
- Strict multi-tenant row-level access control enforced at the service and route dependency levels.
- Strict image upload sandboxing with dimension, format, MIME, size, and hash verification.
- Safe path resolution preventing directory traversal during PDF export and download.
- Zero exposed credentials or secrets committed to active code or Git history.

## 3. Deep-Dive Security Domain Analysis

### A. Authentication & Session Management
- **Password Storage:** Uses Python `hashlib.pbkdf2_hmac` with `sha256`, 600,000 iterations, and a 16-byte cryptographically secure random salt generated via `os.urandom(16)`.
- **JWT Signature:** Signs tokens using `HS256` with a high-entropy secret (`JWT_SECRET_KEY` generated via `secrets.token_urlsafe(48)`). Tokens have a 60-minute expiry (`exp` claim) and subject (`sub` claim) mapped to user UUID.
- **Account State Verification:** Every authenticated request verifies `user.is_active is True`. Inactive or deactivated accounts immediately receive `HTTP 401 Unauthorized` with `"Account is deactivated."`.
- **Privilege Self-Demotion / Self-Deactivation:** Admin endpoints explicitly forbid administrators from demoting or disabling their own accounts (`HTTP 400 Bad Request`).

### B. Authorization & Multi-Tenancy
- **Farm Plots:** Every plot query filters by `farm.user_id == current_user.id`. Foreign key references are verified on creation.
- **AI Reports & Historical Logs:** Predictions, recommendations, disease detections, irrigation advisories, and generated reports enforce strict user scoping.
- **Role-Based Access Control (RBAC):** Admin routes (`/api/v1/admin/*`) require `current_user.role == "admin"`. Non-admin accounts receive `HTTP 403 Forbidden`.

### C. Input Validation & API Hardening
- **Pydantic Validation:** All request payloads are strictly parsed and validated using Pydantic v2 schemas. Unknown or unparsed fields are rejected or sanitized.
- **Numeric & Range Boundaries:**
  - Latitude: `[-90.0, 90.0]`
  - Longitude: `[-180.0, 180.0]`
  - Cultivated Area: `> 0` and `<= 100,000` hectares
  - Soil pH: `[0.0, 14.0]`
  - Soil N, P, K: non-negative physical values
- **SQL Injection Prevention:** 100% of database queries utilize SQLAlchemy ORM or parametrized `select()` expressions. No raw SQL strings or format strings are executed.

### D. File Upload & Serialization Security
- **Plant Pathology Leaf Images:**
  - File extension and declared MIME type checked against an allowed whitelist (`image/jpeg`, `image/png`, `image/webp`).
  - True binary content inspected using `PIL.Image.open()` and `probe.verify()` to prevent disguised polyglot payloads.
  - File size strictly capped at 5 MB (`MAX_UPLOAD_IMAGE_MB`).
  - Image content hashed using SHA-256 and perceptual 64-bit dHash.
- **PDF Report Generation:**
  - PDF files are assigned non-predictable UUID-based filenames (`terraqora_report_<uuid>.pdf`).
  - Reports stored in isolated server directory `uploads/reports/`.
  - Path traversal is physically prevented: file lookup uses strictly normalized, verified paths within `uploads/reports/`.
- **Model Deserialization (Pickle / Joblib / PyTorch):**
  - Model weights (`*.joblib`, `*.pt`) are loaded strictly from the verified local application directory `ml/saved_models/`.
  - No models or serialized code are accepted from external user uploads or untrusted remote endpoints.

### E. Secrets Audit & Git History Scan
- **Exhaustive Automated Search:** Ran regex scans searching for Google API keys (`AIza...`), GitHub tokens (`ghp_...`), private keys, and ngrok tokens across the entire repository.
- **Result:** Zero real secrets found. All matches in the test suite correspond to dummy test strings (`AIzaFakeSecret12345`) specifically designed to verify that error messages scrub credentials before logging.
- **Git History:** Git commit history across all commits (`e29bb37` through `a4af3ba`) is completely clean of real secrets.

TerraQora AI adheres to modern security standards for cloud-native agritech platforms. The application is secured against injection, cross-user data leakage, privilege escalation, and malicious file uploads.
